# IDEF0 «как есть» — контекстная диаграмма A-0

Спецификация для построения в Ramus Educational или draw.io (IDEF0 shape library).
Контекст: классический FedAvg без защиты.

## Единственный блок

**A-0: Цикл федеративного обучения модели (без защиты)**

## Стрелки ICOM

**Входы (Input, слева):**

- I1: локальные обучающие выборки клиентов $\{D_1, \ldots, D_N\}$
- I2: начальные параметры модели $w_0$ (инициализация)
- I3: гиперпараметры обучения (скорость обучения, число локальных эпох, размер пакета)

**Управление (Control, сверху):**

- C1: спецификация протокола FedAvg (правило усреднения, число раундов T)
- C2: критерии остановки (достижение точности, исчерпание бюджета раундов)
- C3: требования нормативных документов (152-ФЗ, приказ ФСТЭК № 21)

**Выходы (Output, справа):**

- O1: итоговые параметры глобальной модели $w_T$
- O2: метрики качества по раундам (точность, потери)
- O3: журналы обучения

**Механизмы (Mechanism, снизу):**

- M1: клиенты (вычислительные узлы с локальными данными)
- M2: сервер-агрегатор
- M3: каналы связи (без криптографической защиты или стандартный TLS)

# IDEF0 «как есть» — декомпозиция A0

Декомпозиция блока A-0 на пять подпроцессов, выполняемых циклически для каждого раунда $t = 1, \ldots, T$.

## Блоки

**A1: Инициализация раунда (сервер).**  
Вход: $w_t$, список клиентов. Выход: выборка клиентов раунда $S_t$, параметры $w_t$ для рассылки. Управление: стратегия выборки клиентов (в межустройственном сценарии — случайная подвыборка с долей $q$). Механизм: сервер.

**A2: Рассылка параметров (сервер → клиенты).**  
Вход: $w_t$, список $S_t$. Выход: копии $w_t$ у каждого выбранного клиента. Механизм: каналы связи.

**A3: Локальное обучение (клиенты).**  
Вход: $w_t$, локальная выборка $D_k$, гиперпараметры. Выход: обновление $\Delta_k = w_t^{(k)} - w_t$. Управление: алгоритм оптимизации (SGD с моментумом). Механизм: клиент $k$.

**A4: Передача обновлений (клиенты → сервер).**  
Вход: $\{\Delta_k\}_{k \in S_t}$. Выход: набор обновлений на сервере. Механизм: каналы связи.

**A5: Агрегация и обновление модели (сервер).**  
Вход: $\{\Delta_k\}$, текущие параметры $w_t$. Выход: $w_{t+1}$, метрики. Управление: правило усреднения FedAvg, веса по размеру выборки клиента. Механизм: сервер.

## Межблочные стрелки

- A1 → A2: $w_t$, $S_t$
- A2 → A3: $w_t$ (копия у каждого клиента)
- A3 → A4: $\{\Delta_k\}$
- A4 → A5: $\{\Delta_k\}$ (на сервере)
- A5 → A1 (следующий раунд): $w_{t+1}$

## Особенность «как есть»

На данной диаграмме отсутствуют блоки фильтрации вредоносных обновлений, внесения дифференциального шума и аттестации исполнительной среды. Все обновления учитываются с равным весом; сервер имеет прямой доступ к индивидуальным $\Delta_k$.
